# M100 Bot

Telegram-бот для мастера: дневной отчёт текстом или голосом → распознавание работ и объёмов
с помощью LLM → подтверждение → запись в Google-таблицу и Битрикс24.

> Статус: бот собран целиком: текст и голос → карточка → подтверждение → таблица, журнал,
> Битрикс24 (через очередь с повторами), `/today`, вопросы «сколько осталось».

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
cp .env.example .env        # заполнить переменные
pytest                      # офлайн-тесты на tests/fixtures/sample.xlsx
python -m m100bot
```

## Настройка .env

| Переменная | Где взять |
|---|---|
| `BOT_TOKEN` | @BotFather → /newbot |
| `LLM_BASE_URL`, `LLM_MODEL` | локальная Ollama: установить с ollama.com, `ollama pull qwen3:8b`, задать переменную `OLLAMA_CONTEXT_LENGTH=8192` |
| `STT_API_KEY` | Groq: console.groq.com → API Keys. Пусто — голосовые не принимаются (бот просит текст). `STT_MODEL` — `whisper-large-v3-turbo` (по умолчанию) или `whisper-large-v3` |
| `GOOGLE_CREDENTIALS_FILE` | Google Cloud → сервисный аккаунт → JSON-ключ; включить Sheets API; расшарить таблицу на e-mail аккаунта |
| `SPREADSHEET_ID` | часть URL таблицы между `/d/` и `/edit`. Таблица должна быть **Google Таблицей**: если загружен `.xlsx`, откройте его в Drive → «Файл → Сохранить как Google Таблицы» и возьмите ID новой |
| `BITRIX_WEBHOOK_URL` | Битрикс24 → `https://<портал>/devops/` (раздел «Разработчикам») → Другое → Входящий вебхук, права **crm**. Пусто — Битрикс не используется |
| `BITRIX_ENTITY_TYPE_ID` | ID смарт-процесса «Дневной отчёт» — число из адреса `/crm/type/<число>/` (его же покажет `try_bitrix.py check`) |

### Проверка подключения к таблице

```powershell
python scripts/try_sheets.py          # только чтение: справочник, план — ничего не меняет
python scripts/try_sheets.py --write  # создаст столбец даты, запишет 1 в строку 17, прочитает обратно
```

`--write` меняет таблицу — запускайте на копии. Скрипт заодно проверяет, что формула
«Выполненный объем» (`=SUM(J:CZ)`) учла новый столбец.

### Битрикс24: смарт-процесс «Дневной отчёт»

CRM → Смарт-процессы → создать «Дневной отчёт», затем в настройках полей добавить
пользовательские поля. Бот находит их **по названию** (коды вида `ufCrm8_…` Битрикс назначает
сам), регистр и «ё» не важны:

| Название | Тип | Что пишет бот |
|---|---|---|
| Дата отчёта | Дата | день работ |
| Мастер | Строка | имя мастера из Telegram |
| Telegram ID мастера | Строка | чтобы отфильтровать отчёты мастера |
| Объёмы | Строка (многострочная) | объёмы этого отчёта, по строке на позицию |
| Ссылка на таблицу | Строка | ссылка на Google-таблицу |

Один элемент = один подтверждённый отчёт: мастер нажал «✅ Записать» — в CRM появился
элемент «Отчет от 03.11.2026 14:35» с объёмами этого отчёта. Второй отчёт за день — второй
элемент.

«Исправить сегодняшнее» меняет элемент того отчёта, где была позиция, — строка получает
пометку «(исправлено, было 15 м)». Если позиция была в нескольких отчётах за день,
прибавка уходит в последний отчёт, а уменьшение снимается сначала с последнего, потом с
предыдущих (не ниже нуля): сумма по отчётам всегда равна значению в таблице.

Отправка идёт через очередь `bitrix_outbox` в SQLite: сразу после записи в таблицу бот в фоне
отправляет элемент (мастер этого не ждёт); если не вышло — фоновая задача раз в минуту
повторяет с паузами до 15 мин. Задание лежит в SQLite и переживает перезапуск бота. id
созданного элемента бот хранит у себя (таблица `reports`), поэтому исправление обновляет
именно его.

```powershell
python scripts/try_bitrix.py check   # только чтение: вебхук, смарт-процесс, поля
python scripts/try_bitrix.py send    # создаст элемент «Отчет от … (проверка бота)» и обновит его
```

`send` пишет в Битрикс: каждый запуск создаёт новый тестовый элемент — потом удалите вручную.

## Как работает бот

1. Мастер присылает отчёт текстом или голосовым. Бот отвечает карточкой: нумерованный список
   `✅` (готово), `⚠️` (больше остатка по смете, запись не блокируется), `❓` (нужно уточнить).
2. Неоднозначные позиции бот уточняет по одной за раз: варианты — списком в тексте, на
   кнопках номера. Если не назван объём или единицы другие — спрашивает число.
   Работы можно присылать и по одной: пока отчёт не записан, новые сообщения дописываются
   в него. Если незаписанный отчёт остался со вчера, бот спросит, дописать в него или
   начать новый.
3. Кнопки карточки: «Записать» (пишет готовое, остальное остаётся в карточке), «Исправить»
   (выбрать номер → новый объём или удалить), «Добавить», «Отмена».
4. После записи — итог и кнопка «📊 Открыть таблицу». `/today` — что записано сегодня, с
   возможностью исправить; `/table` — ссылка на таблицу.

Без нажатия «Записать» бот в таблицу ничего не пишет. Кнопки старых карточек не работают
(в них зашит отпечаток черновика), поэтому нажатие на устаревшую карточку ничего не запишет.

**Надёжность записи.**
- *Сдвиг строк.* Вместе с позицией в черновике хранится её № (колонка A) и название. Перед
  записью бот сверяет их с таблицей: если кто-то вставил или удалил строку, пока отчёт ждал
  подтверждения, бот ничего не пишет и просит прислать отчёт заново.
- *Сбой посреди записи.* Перед записью в таблицу бот сохраняет в SQLite «намерение» (какие
  ячейки, что было и что станет). Если ответ Google потерялся, журнал не сохранился или бот
  упал, повторное «Записать» сверяет ячейки: уже «после» — только дописывает журнал, ещё «до» —
  пишет, ни то ни другое — ничего не трогает и просит проверить вручную. Пока запись не
  закрыта, отчёт нельзя менять («✖️ Отмена» снимает намерение).
- *«Исправить» и «Очистить»* меняют только долю этого мастера в общей ячейке: бот пишет
  разницу к его итогу по журналу, объёмы других мастеров остаются. Если в ячейке меньше, чем
  записал мастер (правили вручную), бот не пишет и просит проверить.
- *Дата отчёта.* Объёмы пишутся в день, когда пришло первое сообщение отчёта, а не в день
  нажатия «Записать»: отчёт от 23:40, подтверждённый в 00:05, попадёт во вчерашний столбец.
  Дата видна в заголовке карточки («Отчёт за 02.11.2026»).
- *Несколько сообщений подряд* (голосовое и сразу текст) дописываются в один отчёт — решение
  «дописать или новый» принимается под блокировкой мастера, второе не затирает первое.
- *Старые кнопки /today* (список открыли вчера) не правят сегодняшний день.
- *Сбой Telegram после записи* не выглядит как ошибка: итог приходит новым сообщением, чтобы
  мастер не прислал отчёт повторно.
- *Ограничения:* если человек правит ту же ячейку в ту же секунду, когда пишет бот, правка
  может перезаписаться — Google Sheets не даёт заблокировать ячейку. В Битриксе при потерянном
  ответе на создание элемента возможен дубль (повторять `crm.item.add` вслепую нельзя);
  ошибка настройки Битрикса (нет поля, нет прав) пишется в лог как ERROR, повтор раз в час.

**Вопросы «сколько осталось».** «Сколько осталось по кабелю 3х2,5?» — бот отвечает
«По смете 182 м, выполнено 112 м, осталось 70 м» (выполнено — из колонки I, без кэша).
Отчёт или вопрос — решает та же LLM (поле `intent`); сообщение с объёмом сделанной работы
всегда отчёт. Вопрос не трогает незаписанный отчёт. Подходит несколько позиций — бот
спрашивает, по какой.

**Голосовые.** Распознаются через Whisper в Groq (нужен `STT_API_KEY`). Бот сначала
показывает «Распознал: …», дальше всё как с текстом, в любом режиме: на вопрос «сколько?»
можно ответить голосом, числа словами («пятнадцать», «семь с половиной») понимаются.
Голосовые длиннее 5 минут не принимаются. Аудио уходит в облако Groq; если сервис недоступен
(в т.ч. по региону), бот просит прислать текст. Без ключа голос не принимается.

**Синонимы — вручную.** Если модель систематически путает фразу, администратор добавляет
строку на лист «Синонимы» той же таблицы: A — фраза мастера («медянку 12 7»), B — номер
строки позиции (19), C — название позиции (для проверки: если таблицу сдвинут и название
в строке B станет другим, синоним пропускается с предупреждением в логе). Синоним проверяется
раньше модели, бот подхватывает лист в течение нескольких минут, перезапуск не нужен.
Объём во фразу не пишите: «12 хомутов» и «хомутов» — один и тот же синоним.

Сам бот синонимы **не пишет**: раньше он запоминал варианты, выбранные мастером кнопкой, но
одно случайное нажатие навсегда закрепляло общее слово («гофру», «хомутов») за одной строкой,
и бот переставал спрашивать там, где обязан. Поэтому синонимы добавляет только человек, и
только для фраз, однозначных по смыслу.

**Доступ.** Только пользователи из `ALLOWED_USER_IDS` (через запятую). Незнакомцу бот
отвечает его Telegram ID, чтобы тот передал его администратору. Пустой список — бот отвечает
всем (предупреждение в логе при запуске).

**Запуск.** В `.env` нужны настоящие `BOT_TOKEN` (@BotFather) и `SPREADSHEET_ID`; Ollama
должна быть запущена. `python -m m100bot` создаёт `data/bot.sqlite3` (черновики, журнал
записей с `prev_value`, очередь Битрикса) и раз в минуту отправляет очередь в Битрикс.

### Принятые решения по сопоставлению

- Если объём не назван, позиция в «шт» и сказано в единственном числе («поставили автомат») —
  объём 1; в остальных случаях бот переспрашивает.
- Любая работа, которой нет в смете, помечается «нет в смете», бот ничего не подставляет.
- Запись идёт только в названную строку: «проложили кабель 3х2,5» — в строку кабеля, без строки
  работ «Прокладка силовых кабелей в трубе»; «поставили автомат» — в строку автомата, без
  «Установка АВ на DIN-рейку». В образце таблицы строки работ не заполнены.
- Размер без материала («шестёрка», «девятка») не угадывается: бот предлагает все позиции
  с этим размером (медь, изоляция, капиллярная трубка).
- Строки 48/49 «Сверление отверстий Д80» с одинаковым названием — бот всегда спрашивает,
  на кнопках указано к-во по смете. Ждём ответа работодателя, какая строка к чему относится.
